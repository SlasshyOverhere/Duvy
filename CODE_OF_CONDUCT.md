# Code of conduct

## The short version

Be decent. Argue about code, not people. Assume good faith until it is clearly absent.

## Expected behaviour

- Keep discussion technical and specific. Critique the change, not the person.
- Accept that maintainers may decline work that does not fit the project, and ask why once.
- Respect privacy. Do not post another person's logs, credentials, IP addresses or personal data.
- Respect the project's boundaries: no piracy links, no bundled media, no requests to add
  scrapers or sources that ship copyrighted content.

## Not acceptable

- Harassment, insults, threats, or sustained disruption in issues, pull requests or discussions.
- Discrimination based on who someone is.
- Publishing private information without permission.
- Using the project's spaces to distribute malware, pirated content or credentials.

## Scope

This applies to the repository's issues, pull requests, discussions, commit messages and any
project space. It does not govern private conversations outside the project.

## Reporting and enforcement

Report a problem to the maintainer privately through GitHub (`@SlasshyOverhere`). Include what
happened and links where possible. Reports are handled quietly.

The maintainer may edit or delete comments, close threads, or block accounts. A first response is
usually a warning; repeated or severe behaviour leads to a ban. There is no appeal committee for a
single-maintainer project, but a decision can be revisited if new information appears.

Security vulnerabilities are handled through [SECURITY.md](SECURITY.md), not this process.
